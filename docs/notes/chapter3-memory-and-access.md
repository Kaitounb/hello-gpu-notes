# 第 3 章 · GPU 体系结构（下）：数据存储与访问

> Datawhale 85 期 hello-gpu · Part 0
> 对应教程：`docs/part0-intro/chapter3`

## 一句话

第 2 章解决了「谁来做」，本章补上「数据在哪、怎么取、什么时候需要线程之间交接」。同一个数组加法，从看一个线程的读写，扩展到看一组线程的访问。

## 三个位置

还是 `c[2] = a[2] + b[2]`（3 + 30）：

| 位置 | 名称 | 放什么 |
| ---- | ---- | ---- |
| 数组存储区 | **全局内存（Global Memory）** | 输入 `a`、`b`，输出 `c` |
| 靠近计算部件的临时位置 | **寄存器（Register）** | 当前指令用到的输入和中间结果 |
| 执行运算的部件 | **执行单元** | 用寄存器里的值计算，产生新值 |

「全局内存」描述程序的访问空间，「显存」描述承载数据的硬件。图的示意不代表芯片面积、物理距离或完整硬件结构。

寄存器由编译器安排，源码里的变量不一定与寄存器一一对应。

## 一次加法的完整回合

**读入两个输入 → 执行加法 → 写回一个结果。**

- 读完之后，`a[2]`、`b[2]` 里的 3、30 仍然保留；线程拿到的是供计算使用的值。
- 加法先得到临时值 33，**此时 `c[2]` 还没更新**；写回完成后输出数组才拿到它。
- 数组已经在 GPU 上，不等于执行加法的部件已经拿到了操作数。保存值与使用值计算，是两个不同的职责。

## 合并访存

把视野扩大到同一 wavefront：执行一条读取指令时，每个 lane 提供自己的地址，硬件面对的是一组请求。

| 排列 | 四个 lane 读 | 结果 |
| ---- | ---- | ---- |
| 集中 | 下标 0、1、2、3 | 同一段数据可能满足多个线程 |
| 分散 | 下标 0、5、10、15 | 可能涉及更多数据块，其中只有部分元素被使用 |

硬件把同一 wavefront 的访存请求尽量合并处理，叫**合并访存（Memory Coalescing）**。写程序时让相邻线程访问相邻元素，通常更有利，但实际合并由硬件完成——不能只凭示意图断言某张卡一定发生几次事务。

FP32 每元素 4 字节，连续下标 0、1、2、3 对应字节偏移 0、4、8、12。

## 缓存与 LDS 不是一回事

| | 缓存（Cache） | LDS（Local Data Share） |
| ---- | ---- | ---- |
| 谁管理 | 硬件 | 程序显式安排 |
| 作用 | 保存访问过的数据副本，命中就不必再往下层取 | 同一 block 内线程之间交接中间结果 |
| 声明 | 无需声明 | `__shared__` |
| 同步 | 不需要 | 需要屏障 |

- 缓存按**缓存行（Cache Line）**保存副本，找到叫**命中（Hit）**，没找到继续往后面的层级请求。
- 合并访存关注这一批请求的**地址排列**，缓存关注所需数据**是否已有副本**。
- LDS 的声明不会自动复制输入或交换结果，谁写、谁读都要程序安排。
- 简单数组加法没有交接需求，不必经过 LDS。

## 求和例子：LDS + 屏障

把 `[1, 2, 10, 20]` 求总和，甲算前两个（3），乙算后两个（30），甲最后合并：

1. **写**：甲写 `shared[0] = 3`，乙写 `shared[1] = 30`。
2. **同步**：`__syncthreads()`。不同 wavefront 不必同时推进，甲写完自己的位置不能证明乙也写完了。
3. **读**：甲读 `shared[0]` 和 `shared[1]`，相加得 33。

屏障保证**屏障之前的共享写入对组内线程可见**；block 中全部线程都要到达它，不能让部分线程绕过。

但屏障不会替程序修复越界或互相覆盖这类错误，它只建立先后关系。

## 访存等待与延迟隐藏

wavefront A 发出读取请求、数据还没回来，依赖它的加法暂时不能执行。这时调度器（Scheduler）可以选择同一资源上另一条已就绪的 wavefront B 来执行。

- A 的临时值和执行状态仍然保留，不需要把 A 当作已完成。
- 也不需要 CPU 手动切换这两个 wavefront。
- 这叫**延迟隐藏（Latency Hiding）**：A 的读取**没有因此更早返回**，只是执行资源在等待期间做了别的工作。
- 如果其他 wavefront 也都在等，或者需要的执行资源正忙，仍然可能空闲。
- 同时保留多组工作需要寄存器等片上资源，所以可供选择的工作数量有上限（见原文「执行资源与访存实验」）。

## 容易混

- 「数据在 GPU 上」≠「执行单元已拿到操作数」。
- 「共享位置存在」≠「值已经准备好」。
- 共享 ≠ 所有线程同时写完；屏障 ≠ 自动修复错误。
- 延迟隐藏 ≠ 消除延迟。

## 本章小结

- 输入输出数组在全局内存，临时值在寄存器，执行单元负责运算；算完还要写回输出。
- 看访存要观察同一 wavefront 的地址排列；集中请求更有机会合并，缓存可能提供已有副本。
- 需要其他线程的中间结果时，用 LDS 安排交接，用 block 同步保证先写后读。
- 一个 wavefront 等待数据时，调度器可以执行其他就绪指令：利用了等待时间，但没有消除访问本身的延迟。
